# 走らせて確かめる試験

サーバーを手元で起動し、ダイヤ運転・自動運転列車アリにして、ロープレ時刻を早回しで進めます。
走っている間、画面と同じ API から列車の様子を読み続け、「決まり」を破ったら失敗にします。
ゲーム（TRAIN CREW）もクライアントも要りません。

## 走らせ方

リポジトリのいちばん上のフォルダで:

```
dotnet run --project Gokko.Tests
```

- 既定は、下の場面を全部、8倍速で、同時に5本。13分ほどで終わります（`--parallel 10` なら8分ほど）。
- 名前で選んで1つだけ走らせるとき: `dotnet run --project Gokko.Tests -- --only 抑止`
- 1つの時間帯だけ短く見るとき: `dotnet run --project Gokko.Tests -- --slices 17:30 --minutes 30`
- 決まりを破ると、終了コードが 1 になり、どの列車が・いつ・何を破ったかを出します。
- 記録（サーバーの記録・進路の記録・自動運転の状態の記録・在線の記録・入れた操作）は `Gokko.Tests/out/場面/` に残ります。

PR を出す・main に入れると、GitHub でも自動で走ります（`.github/workflows/sim-test.yml`）。

## 走らせる場面（`Scenarios.cs`）

| 場面 | 中身 |
|---|---|
| ダイヤどおり（5:00・7:30・12:00・17:30・22:30 から 60分ずつ） | 何も操作しない |
| 抑止して外す（17:30 から 40分） | 走っている列車3本を先の駅で抑止し、6分後に外す |
| 番線を変える（12:00 から 40分） | 複線の駅で、これから着く駅の番線をほかの番線に変える（6本） |
| 臨時停車と打ち切り（7:30 から 40分） | 通過する駅に臨時停車を3本、途中の駅で打ち切りを1本 |
| 時刻を飛ばす（17:30 から 40分） | 走らせている途中で、ロープレ時刻を 19:00 に飛ばす。**既知の不具合**（列車が倍になって詰まる）を再現する場面で、破っても落とさない |
| 自動運転の切り入れ（12:00 から 30分） | 自動運転列車をナシにして全部消し、1分後にアリに戻す |

操作する列車は、そのとき走っている列車から選びます（どの列車に何をしたかは、結果と `operations.txt` に出ます）。

## 見張っている決まり（`Rules.cs`）

| 決まり | 中身 |
|---|---|
| 同じ回路 | 同じ軌道回路に2本の列車が 40秒より長くいない（連結する増結車・切り離した車両は除く） |
| 詰まり | 自動運転の列車が、進路待ち・信号の手前・連結待ち・入換待ちのまま、同じ場所で 12分より長く止まらない |
| 同じ列番 | 同じ列番が2本いない。呼び分けの接尾辞（X・Y・Z・#2）の付いた列車が出ない |
| 出現待ち | 現れた列車が、5分より長く出現待ちのままにならない |
| 残った進路 | 列車がいなくなったのに、その列車の進路が 2分より長く在線位置に残らない |
| エラー | サーバーの記録に、エラー・例外が出ない |

時間はロープレ時刻です。

## 見られないもの

- ゲームをつないだ列車（運転士の操作・継続乗務・X線入換・車掌）。自動運転の列車だけで走らせます。
- 司令員の操作のうち、出発順序・走行順・後運用の差し替え・特発臨・直接折返・途中折返し。単線の交換駅の番線の変更（対向列車のいる番線に変えると、指示どおりに両方が動けなくなるので、試験では触らない）。
- 信号制御盤（ラインライト）と、画面の見た目。
- 早回しなので、実時間で数える待ち（止まってから何秒、など）は、ロープレ時刻では8倍の長さになります。

## バグを直したら

1. そのバグが、今の場面と決まりで捕まるかを考える。捕まらないなら、`Scenarios.cs` に場面（時刻と操作）を、`Rules.cs` に決まりを足す。
2. 直す前のコードで試験が落ち、直したあとで通ることを確かめる。
3. すぐに直せない既知のものは、場面ごとなら `Scenarios.cs` の `KnownIssue` に、列車ごとなら `known.txt` に、理由と一緒に書く（試験は落ちないが、結果には出続ける）。

# データの突き合わせ

同じこと（進路が通る軌道回路・接近の回路・信号機や回路の名前）が、何か所にも手で書いてあるので、食い違いと書きまちがいを機械で探します。
サーバーは起動しません。数秒で終わります。

```
dotnet run --project Gokko.Tests -- --data
```

## 見ているもの

| 種類 | 中身 |
|---|---|
| 誤り | 回路・信号機・進路・駅の名前が、元の一覧にない。盤の進路が指すてこ・着点・転てつ器が盤にない。直すしかないもの |
| 食い違い: 通る回路・接近の回路 | 進路のデータ（`Interlockings.json`）と、信号制御盤・電子連動装置の駅のデータで、同じ進路の回路が違う |
| 食い違い: 過走防護 | 盤で過走防護にしている回路が、進路のデータの通る回路に入っている |
| 食い違い: 盤のデータが2つ・盤のない駅・盤にない進路・灯だけの信号 | 盤のデータの過不足 |
| 食い違い: 在線位置に線がない | 進路が通る回路が、在線位置の線（`tid-layout.json`）にない |
| 食い違い: 回路の長さがない | 進路が通る回路の長さが、自動運転列車の表（`AiTrains.json`）にない |

盤の進路は、過走防護の回路も回路に入れています（鎖錠のため。ラインライトは点けません）。通る回路を比べるときは、それを除いています。

## わざとの食い違い（`data-known.txt`）

- わざと違えているもの・まだ決めていないものは、`data-known.txt` に理由と一緒に書きます。書いてあるものは落としません。
- 書いていない食い違いが出たら落ちます。データを直すか、わざとなら理由を書いて足します。
- 直して食い違いがなくなった行は、突き合わせが「もう食い違っていません」と知らせるので消します。
- `dotnet run --project Gokko.Tests -- --data-list` で、今ある食い違いを、そのまま書ける形で出せます。
